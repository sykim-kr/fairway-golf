CREDENTIAL GUIDE
GTM API 정보 발급 방법
1. 컨테이너 식별자 확인
  1. Google Tag Manager에서 생성한 Web 컨테이너를 엽니다. 상단의 GTM-XXXXXXX가 공개 ID입니다.
  2. 관리 → 사용자 관리에서 본인에게 컨테이너 게시(Publish) 권한이 있는지 확인합니다.
  3. 워크스페이스 주소의 accounts/숫자/containers/숫자/workspaces/숫자에서 첫 번째 숫자는 Account ID, 두 번째 숫자는 API Container ID입니다. 마지막 Workspace ID는 입력하지 않습니다.


2. Google Cloud에서 OAuth 클라이언트 준비
  1. Google Cloud Console에서 프로젝트를 선택하고 Tag Manager API를 사용 설정합니다.
  2. Google Auth Platform에서 앱 이름·지원 이메일과 대상 사용자를 설정합니다. 테스트 상태라면 GTM 계정의 Google 이메일을 테스트 사용자로 추가합니다.
  3. OAuth 클라이언트를 웹 애플리케이션 유형으로 만들고 승인된 리디렉션 URI에 https://developers.google.com/oauthplayground를 추가합니다.
  4. Client ID와 Client Secret은 다음 단계의 Google OAuth Playground에서만 사용합니다. 이 페이지에는 입력하지 않습니다.


3. OAuth 액세스 토큰 발급
  1. Google OAuth 2.0 Playground를 열고 톱니바퀴 → Use your own OAuth credentials에 방금 만든 Client ID·Client Secret을 입력합니다.
  2. Step 1의 scope 입력에 아래 세 URL을 공백으로 구분해 입력하고 Authorize APIs를 누릅니다. GTM 게시 권한이 있는 계정으로 로그인하고 요청 권한을 확인합니다.
  1. Step 2에서 Exchange authorization code for tokens를 누릅니다.
  2. 응답의 access_token 값만 위 입력란에 붙여 넣습니다. Bearer 접두사, refresh_token, client_secret은 넣지 않습니다.
  3. 토큰은 만료됩니다. 401 오류가 나면 Playground에서 새 액세스 토큰을 발급해 다시 입력합니다. 이 페이지는 자동 갱신용 비밀키를 저장하지 않습니다.


4. GitHub 저장소 전용 토큰 발급
  1. GitHub Fine-grained token 생성에서 이름과 짧은 만료일을 지정합니다.
  2. Resource owner는 sykim-kr, Repository access는 Only select repositories → fairway-golf를 선택합니다.
  3. Repository permissions의 Contents → Read and write를 부여합니다. Metadata 읽기는 기본 권한입니다.
  4. Generate token 후 나온 값을 위 GitHub 입력란에 붙여 넣습니다. 이 토큰은 GitHub API에만 전송되며 페이지 소스나 커밋에 포함되지 않습니다.
API Key만으로는 GTM을 수정·게시할 수 없습니다. Google OAuth 권한과 GTM 사용자 게시 권한이 모두 필요합니다. 오류 403은 범위·계정 권한·API 사용 설정을, GitHub 409/422는 브랜치 보호나 동시 수정을 확인하세요.
